# Day 5/100: System Attack Vectors & Vulnerabilities 🛡️

Welcome to Day 5 of my SOC Analyst journey! Today was all about understanding how an attacker actually gets into a system and what gaps they look for. Without knowing the "Path" and the "Weakness," a SOC Analyst is essentially monitoring in the dark.

## 📌 The Concept: Home Security Analogy
To keep it simple and relatable, I’ve broken down these technical terms using a daily life example:

| Term | Analogy | Technical Definition |
| :--- | :--- | :--- |
| **Vulnerability** | A broken door lock or an open window. | A flaw or weakness in a system's design, implementation, or operation (e.g., Unpatched software, Weak passwords). |
| **Attack Vector** | The path the thief took (Backyard, Roof, or Front door). | The path or means by which a hacker gains access to a computer or network server (e.g., Phishing emails, Malicious USBs, Open Ports). |

## 🧠 The "Day 5" Realization (SOC Perspective)
During my study today, I realized a common mistake: Many people focus only on fixing **Vulnerabilities** (Patching) but ignore the **Attack Vectors** (Monitoring the entry points). 

As a **SOC Analyst L1**, my job isn't just to see that a system is weak; it’s to correlate these two. If I see a specific "Vector" (like a suspicious email) targeting a known "Vulnerability" (like an outdated browser), that’s an alert I need to neutralize immediately!

## 🛠️ Key Takeaways for SOC L1:
*   **Vulnerability Scan != Monitoring:** Scanning tells you what's broken; SOC monitoring tells you who is trying to exploit it.
*   **Human Factor:** Humans are often the most exploited attack vector (Social Engineering).
*   **Correlation is Key:** An attack only happens when a Vector successfully hits a Vulnerability.
